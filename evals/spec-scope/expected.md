# Expected behavior

A: Deliver direct filtered CSV export with authorization, escaping, applicable rate limits, cancellation, and observable error handling. Keep background delivery outside the spec. Avoid a mandatory experiment framework or general interview.
B: Identify that automatic retries cannot establish the no-duplicates guarantee under the supplied provider facts. Explain the changed assumption and return the larger design/scope decision to the user, with a smaller or replacement proposal. Do not silently append infrastructure or erase accepted guarantees/work.
C: Provide a small concurrency fix with atomic enforcement and a meaningful concurrent-request test. Preserve authorization and error behavior. Do not trade correctness for brevity or introduce a general reservation platform.
D: Specify one complete import verified at the existing importer or provider-client seam, with validation before mutation and success reported only from complete evidence. A lower seam is acceptable if it proves the full contract without a live provider. An unexpected response fails closed and leaves the catalog unchanged. Keep retry, crash resume, reconciliation, repair loops, and provider-failure taxonomies outside v1 because no evidence or promised outcome requires them. Include an architecture constraint only if it is part of the required outcome, and do not prescribe file or module cleanup.

E: Produce one compact unattended-execution contract. It should say that the agent continues until the Epic is complete and verified, human action is required, the operator cancels, or an explicit limit is reached. Failed child work must not advance execution or alter accepted work. Safe failures may be retried; unsafe or unproductive progress must stop with a reason. Restart should continue from the last safely established accepted point, ambiguous state should stop, and a blocked run should not loop automatically across restarts. Express these as general workflow rules and a small set of observable acceptance criteria. Do not enumerate worker error types, prescribe retry counts, or design persistence and recovery machinery.

F: Each child merges to `main` before the next starts, so each must be safe to merge alone: existing behavior preserved, touched behavior complete, no half-finished user flow. Keep the new data path unreachable from users until the child that completes the flow. Prefer a split that needs no feature flag or compatibility layer; if a child cannot be safe alone, merge it with its neighbor.

G: Recognize that existing per-launch logs already answer the goal: per-stage cost comes from each log's raw `turn.completed` event, attributed by run directory and filename, and peak context comes from provider traces while they exist. Run that analysis now (a logged shape decision) instead of specifying a telemetry store, pre-launch or atomic records, pruning-proof snapshots, or live-writer tolerance. If the human needs the view repeatedly, only a minimal read-only summary. Correct the cache-write claim: the raw event reports `cache_write_input_tokens`, and the wrapper's zero is not evidence. Keep peak per-request input separate from cumulative totals, and never turn unknown into zero. Surface dropped draft requirements to the user. Observed failure: the drafted contract designed a new telemetry subsystem and asserted an unreported field from wrapper output.

H: Restate the goal as the human's objective: cheaper deliveries without worse outcomes. Treat "find the context range" as a hypothesis about how to get there, not the goal. Before specifying any recording, use the evidence that already exists: launch logs carry raw usage, and rollouts carry per-request input, compaction, model, and effort. Recommend a one-off analysis of those logs to find where tokens actually go, run it, and report the result rather than finalizing new telemetry. If the human still wants recording, specify only the one missing fact, the pass decision, as a small best-effort record, with no CLI, sidecars, classifications, or duplicated fields. List the dropped draft requirements. Observed failure: the skill turned this request into a large measurement contract (pass records, launch-only rows, sequence numbers, duplicate handling, compaction and work-size fields, an inspection CLI) whose value depended on a future analysis, while a direct look at existing logs showed the cost mechanism and a small prompt-level fix.

Judge scope, correctness, and user decision boundaries rather than headings or wording.
