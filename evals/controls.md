# Maintained controls

These records describe accepted corrections from the agent-assisted engineering audit. Evidence and exact file digests for the first evaluation are in `results/2026-09-10.md`. This document records ownership, not a requirement to add a permanent instruction after every correction.

| Cause and consequence | Owner and control | Behavioral case | Review or retirement condition |
| --- | --- | --- | --- |
| A committed-only review omitted current work and could miss defects. | `implement` supplies the candidate; `code-review` includes selected dirty and new files, inspects evidence, and returns findings for revalidation. | `review` | Revisit when candidate capture or review tooling changes. Retire procedural detail if equivalent tooling enforces the same guarantees. |
| New interface tests could erase historical regression proof. | `codebase-design/DEEPENING.md` requires transferred relevant coverage before test retirement. | `retirement` | Revisit when the affected behavior is intentionally removed or replacement tests discriminate every retained claim. |
| A wizard reported success despite skipped required configuration. | `wizard/template.sh` owns required/optional status and final exit code. | `test_wizard.py` | Revisit when the helper API or external-write confirmation changes. Preserve the outcome tests while those guarantees remain relevant. |
| A resumed task could reuse stale verification or lose unfinished work. | `handoff/CONTINUATION.md` owns the packet; the active workflow updates it and reconciles live state. | `continuation` | Replace the fallback record when the active executor provides an equivalent authoritative one. Keep resume checks at that owner. |
| An outdated router restarted settled design work. | `ask-matt` routes from current intent and evidence, and `tdd` reuses agreed seams. | `routing` | Revisit when a routed skill's admission or completion contract changes. Compare unnecessary questions and stages as well as correctness. |
| A ticket breakdown can mirror internal responsibilities or combine several behavioral milestones into a mini-Epic. The first produces prerequisite-only tickets; the second overloads one implementation context with unrelated failure models and state transitions. | `to-tickets` requires every slice to advance the parent workflow and remain cognitively coherent. Review rejects both prerequisite-only tickets and slices with multiple independently substantial behaviors. | `vertical_slices` | Revisit when ticket-sizing or executor-routing rules change. Retire the wording only if another enforced review applies both the verticality and cohesion tests. |
| A proof-only authorization or environment gate can block otherwise executable implementation work. | `to-tickets` separates implementation prerequisites from verification prerequisites and moves externally gated live proof into a downstream validation ticket when local seams can verify the implementation. | `vertical_slices` | Revisit when dependency representation or live-environment validation policy changes. Retire the wording only if another enforced review keeps proof-only gates off implementation tickets. |

The conflict helper now stages only resolved in-scope work. Triage checks that the consumer receives reconciled requirements. Research dispatch depends on a useful independent question. These instruction changes receive consistency review here; they are not claimed to have individual behavioral passes in this initial case set. Add an isolated case when use exposes a consequential failure or the workflow changes materially.

The `to-spec` scope correction is retained in [spec-scope/result.md](spec-scope/result.md), with separated inputs, expected outcomes, and independent responses. It bounds the useful outcome while preserving correctness and returns material design expansion to the user. Review it when routine work is unnecessarily blocked or actual scope growth still escapes reassessment.
