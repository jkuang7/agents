# Issue tracker contract

Before reading or publishing issues, resolve the repository that owns the work
and read its `AGENTS.md` or `CLAUDE.md` files. Follow any tracker instructions
there, including repository-relative files they name.

If the repository has no tracker instructions, use the tracker implied by its
primary remote. If it has no such remote, keep work in local Markdown files
under `.scratch/<feature>/issues/` unless the user names another tracker.

Use the repository's labels when defined. Otherwise use these portable status
labels when the tracker supports them: `needs-triage`, `needs-info`,
`ready-for-agent`, `ready-for-human`, and `wontfix`.

Do not publish, edit, label, or close tracker items without authorization for
that external change.
